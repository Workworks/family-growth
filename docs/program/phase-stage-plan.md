# Phase → Stage 实施排期

需求中的 Phase 0–9 与全局 Stage 1–10 一一映射，详见 [Phase 索引](../phases/README.md)和 [Stage 路线图](../stages/stage-roadmap.md)。每阶段遵循“需求账本 → Spec → 设计 → 实现 → 目标测试 → 真实验证 → 证据回填”，不得跨过 Wallet/Ledger 核心模型直接堆 UI。

| Phase | 全局 Stage | 主题 |
| ---: | ---: | --- |
| 0 | 1 | 项目立项与总体设计 |
| 1 | 2 | 工程骨架与 Family/Growth 基础 |
| 2 | 3 | TaskCompletion、审核与奖励 |
| 3 | 4 | Wallet 与 Ledger |
| 4 | 5 | GiftMoney、兑换与 Coin |
| 5 | 6 | 商店、储蓄与愿望 |
| 6 | 7 | 虚拟基金、NAV、持仓与费用 |
| 7 | 8 | Android 家长/孩子核心页面 |
| 8 | 9 | 跨域业务闭环与报告 |
| 9 | 10 | APK、部署与 V1 总验收 |

Stage 11–15 是用户直接提出的计划外能力，不改变上述业务编号。Stage 15 的儿童最佳利益准则具有产品行为最高优先级，可暂停普通功能 Stage，但不篡改其真实状态。
