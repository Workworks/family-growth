本文是范围审计和待办分解，不替代 Stage 报告。正式实现仍须先建立对应 Stage Spec；完成状态必须以代码、目标数据库、Android 自动化、真机和平板证据为准。

## 1. 当前教学能力事实

当前已具备的只是教学任务基础闭环：

- 服务端有基础 `GrowthPlan → GrowthGoal → GrowthTask`、孩子提交、家长审核和 XP/Coin/Money 奖励。
- Android 本机任务是扁平的标题、分钟数、奖励和 `TODO/SUBMITTED/APPROVED` 三状态。
- “安静小课堂”只有 3 个写死在 APK 内的 18 秒原创视频；累计播放 90% 后提交固定奖励任务。
- 生产同步只返回任务 ID、标题、预计分钟、状态和最近 Completion；没有课程、课节、题目、答案、掌握度或内容版本。
- 学习报告目前主要统计任务数量和学习分钟，不能证明学会了什么。

因此，当前版本可以支持“家长布置一个任务、孩子完成并审核”，但不能支撑完整课程、练习、评估、进阶和内容运营。

## 5. 明确不是待办的边界

- 不接真实银行、微信/支付宝自动支付、证券、真实基金或行情。
- 不做面向儿童的排行榜、连续签到、抽奖宝箱、随机奖励、无限滚动、自动播放或损失施压。
- 不把本 App 防沉迷宣称为系统级跨 App 家长控制。
- iOS、多租户 SaaS、公开社交和开放内容推荐流不是当前范围。

## 6. 建议实施顺序

以下只是建议拆分，尚未建立 Stage 状态事实：

1. 建议 Stage 20：T-01–T-04，确定课程范围并升级课程/教学任务核心模型。
2. 建议 Stage 21：T-05–T-11，建设活动、题库、评估、Completion 和内容安全后端。
3. 建议 Stage 22：T-12–T-17，建设 3–5 岁教学中心、家长教学工作台和原创内容包。
4. 建议 Stage 23：T-18–T-21，建设教学报告、生产同步、离线 outbox 和隐私保护。
5. 建议 Stage 24：T-22 与 E-01–E-06，完成平板端到端、稳定签名 APK 和 Release 验收。
6. 之后按 P-01–P-21 继续产品深度；P-17/P-18 安全与数据权利优先于 P2 财商扩展。
