# 需求治理

`requirement-ledger.md` 是用户需求和建议的长期事实源。它采用追加式维护：不删除旧条目，不用最新描述覆盖历史原意。

## 优先级

| 优先级 | 含义 |
| --- | --- |
| `P0` | 安全、隐私、账本一致性、合规红线或当前交付阻断 |
| `P1` | V1 必须具备的产品闭环与验收能力 |
| `P2` | V1 重要增强，可在主闭环稳定后交付 |
| `P3` | 后续版本候选、探索或优化建议 |

优先级不等于实现顺序；依赖关系、风险和用户后续明确调整可以改变排序，但必须留下变更记录。

## 登记字段与状态

每条记录包含 ID、日期、来源、原始意图、解释/边界、优先级、状态、目标 Stage、落地/验收链接。用户一句话包含多个可独立验收能力时允许拆分，但各条都必须回链同一来源。

状态流转为 `NEW` → `ACCEPTED` → `PLANNED` → `IN_PROGRESS` → `VALIDATED`。不能立即实施时用 `DEFERRED`；违反产品边界时用 `REJECTED` 并说明原因；被新需求替代时用 `SUPERSEDED` 并指向新 ID。
