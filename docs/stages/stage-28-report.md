# Stage 28：奖励预算、兑换额度与履约闭环

状态：`BLOCKED`（可离线工程与自动门禁完成，仅缺 V28-08 目标平板运行态）

产品 Phase：V1 奖励治理 / P1

需求：REQ-001、REQ-027、REQ-050、REQ-051；Backlog P-04、P-05、P-07

## 用户可观察目标

家长可以为每个孩子配置版本化奖励预算，知道今天/本周/本月还可发多少 Money，并选择超限时“等待家长一次性覆盖”“把超出部分按固定比例转为 Coin”或“转为 XP”。Money/Coin/XP 实际结算仍由服务端裁决并保留提议值、实际值和原因。兑换可按方向关闭、设置日/月额度，并要求孩子发起后由家长批准。实体奖励被批准不等于已兑现，家长完成现实履约后明确标记 `FULFILLED` 并写备注。

## 范围内

- `RewardBudgetRule` 按孩子版本化，包含时区、日/周/月 Money 上限、超限策略以及固定 Coin/XP 转换率；新版本激活、旧版本失效并留审计。
- 普通成长任务审核在同一事务读取当前预算与既有已批准事实，计算最严格剩余额度；Money 超出部分按规则处理，实际奖励和决策原子保存。
- `HOLD_FOR_PARENT` 不伪装为审核成功：需先创建绑定 completion、提议奖励摘要和原因的一次性覆盖，再重试审核。覆盖不能跨孩子、跨奖励或重复消费。
- `ExchangeControlRule` 版本化保存 Money→Coin/Coin→Money 开关、每日/月度 source 额度和儿童是否需家长审批；preview 和 confirm 均复验额度/规则漂移。
- 儿童需审批时只创建 `PENDING` 请求，不扣账；家长 `APPROVE` 后才调用既有原子兑换，`REJECT` 无账本副作用。
- 奖励订单增加 `FULFILLED` 终态、履约人/时间/备注/幂等键和动作审计；只有 `APPROVED → FULFILLED`，不能回退或重复履约。
- Android 家长端集中展示预算、兑换护栏、待审批和待履约；孩子端只看到“等待家长回应/已经兑现”等中性状态，不显示预算不足、费率压力或损失语言。

## 范围外

- 自动真实支付、物流、商家核销、推送轰炸、逾期惩罚、连续签到、随机奖品、竞价、排行榜和为了消耗 Coin 制造焦虑。
- 把成长记录、学习时长或里程碑自动换钱；教学奖励仍必须在家长确认的既有 Completion 流程中结算。
- 追溯重算旧奖励；新规则只影响激活后尚未审核的 Completion/新 preview。

## 安全与账本不变量

1. 预算计算、超限转换、覆盖消费和 Completion 审核必须在同一数据库事务；实际 Money/Coin 仍由既有 `reviewCompletion` 在同一事务追加 Ledger 后更新 Wallet。
2. 额度以已确认 `exchange_order` 为事实，不以 preview/待审批请求占用；confirm 时重新校验，两个并发确认最多一个穿过剩余额度。
3. 转换只使用规则中显式固定比例和向下取整，确认响应/决策记录同时返回提议和实际奖励；不隐藏 Money 被压缩或 Coin/XP 增量。
4. 一次性覆盖绑定 family/child/completion/奖励摘要，家长专属、幂等、消费一次；规则和覆盖原因不下发孩子。
5. `FULFILLED` 不改 Wallet/Ledger，只证明家庭现实约定已履行；拒绝/取消/重复履约均不产生账本变化。

## 前端两遍设计

第一遍采用“家庭约定夹”：家长看到三张纸页式卡片——奖励预算、兑换护栏、待兑现约定；每张卡只显示当前规则、明确剩余和一个编辑/处理动作。色彩继续使用松针绿/纸页米色，额度数字用等宽字体但不做红色倒计时或进度环。

第二遍删除儿童端“余额不足”“今天用完”等惩罚语和家长端强警告色；预算超限改为中性确认单，逐行展示提议 Money、预算内 Money、转换 Coin/XP 或覆盖原因。履约按钮文案为“确认已经做到”，必须填写现实备注；不使用庆祝动画或催促通知。
