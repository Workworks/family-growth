# Room 迁移与可靠同步

Stage 30 将 Android 本机业务快照放入 Room，业务 JSON 先由 Android Keystore 的 AES-256-GCM 加密。Bearer Token 仍只在内存，PIN 只保存 BCrypt 哈希；Room 表不得出现 Token、明文 PIN、答案键或家长私密说明。

## 升级与恢复

1. 覆盖安装后保留 App 数据，首次启动读取旧 `family_growth_local/state`。
2. App 依次执行加密写入、解密回读、业务解码和迁移凭据写入；全部成功才删除旧 key。
3. 若提示迁移失败，不要卸载或清数据。先保留现场并记录不含内容正文的异常类型，再使用同签名修复版本覆盖安装重试。
4. Keystore 密钥丢失或密文校验失败时 fail-closed，不回退到明文；由家长重新连接服务恢复服务端事实。本机尚未同步的动作仍需单独核对。

## 同步故障

- `/sync/delta` 的 cursor 只允许前进；known digest 与服务端投影每次最多 2000 项。
- 相同 Idempotency-Key 仅允许完全相同请求和投影重放；否则返回 409。
- tombstone 只删除本机缓存键，绝不触发服务端删除。
- 409 学习动作会保留原幂等键并进入家长冲突列表。先刷新服务端事实，再显式重试或放弃；不要直接改数据库或清 App 数据。

真实完成仍需从 0.3.8 同签名覆盖升级、杀进程重启、断网恢复和两设备并发回放。缺目标设备时必须保持 `BLOCKED`。
